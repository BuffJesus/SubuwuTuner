# Changelog

All notable changes to SubuwuTuner are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/).

Pre-1.0 entries describe substantial state changes rather than strict semver releases. Versioning hardens at v1.0.

## [Unreleased]

### Added
- **COBB AccessPort V3 file-vault integration (T1 + T2 + T3 cipher)** — libusb-backed `st::transport::ets` + `st::devices::ets::Client`. CLI `subuwutuner-cli ap3 {state, ls, pull, push, rm, backup, raw}` + GUI **AccessPort Browser** panel (View → AccessPort Browser): Connect/Disconnect, subdir tabs for /maps + /datalog + /presets + /images, per-row Pull/Remove with inline confirm popup, Push / Backup-all / Refresh toolbar, marriage chip, welcome-panel hint when an AP is detected on USB. Capability A on by default. T3 cipher (XTEA-CBC outer + base64 + AES-256 custom-CTR + bzip2 + Blowfish OTA) gated behind `ST_ENABLE_COBB_AP_CIPHER=ON`; write-side gated additionally on `ST_ENABLE_COBB_AP_PTM_REWRITE=ON`. Marriage gate is load-bearing per spec §6.13 cmd 0x28 UserInfo parse — `Not Installed` refuses operations until `--allow-unmarried-ap`. See `docs/34-cobb-ap-as-tune-vault.md`.
- **`subuwutuner-cli ptm` family** — `list-patches` / `inspect` / `diff` / `import` / `export` subcommands behind `--enable-cobb-ap-cipher`. `ptm import` writes a five-file `.stune` skeleton (`project.toml` with `[ptm_metadata]` + `source.bin` + `working.bin` with patches applied + `edits.toml` with one ByteEdit per patch tagged `ptm_import` + `ptm_patches.toml` round-trip-authoritative source). `ptm export` rebuilds a byte-identical `.ptm` via `encrypt_ptm`. End-to-end cycle live-validated on user's married AP 2026-06-12: AP pull → import → export → AP push → AP pull-back → verify, 4244/4244 patches matched.
- **GUI `.ptm` modals** — File → Import .ptm File…, Inspect .ptm File…, Export as .ptm…, Diff Two .ptm Files… Mirror the CLI surface; the import wizard drops the loaded `st::Project` into AppState in one flow. Status-bar `[ptm_imported]` badge (purple accent chip showing vendor_id from `[ptm_metadata]`) — tooltip surfaces vendor / vehicle / patch count.
- **Interpretation prose for `ptm inspect` / `ptm diff`** — `st::library::interpret_inspect` + `interpret_diff` heuristic generators (8+8 rules, pure templated if-then; no LLM). Wired into CLI text mode (new "Interpretation" / "What changed" sections) and GUI modals.
- **Architectural classifier** — `st::devices::ets::Layer` + `LayerMap` + `classify_patches()` + `summarize()` + `layer_label()` per `docs/35-tuner-overlay-architecture.md`. Most-specific (smallest containing range) match — needed because the spec's range list has intentional overlap (`PrimaryCode` and `SecondaryCode` sit inside `MainCalibration`).
- **Spec §6.0 codec-level block list** — `is_blocked_command` in `st::transport::ets` returns true for cmd bytes that have caused observable AP daze in §4.2 testing (`0x05`, `0x06`, `0x07`/`0x08`, `0x18`, `0x29`, anything `> 0x31`). `encode_packet` rejects these with `PolicyDenied` before bytes hit the wire. Defense-in-depth.
- **History panel — collapsible tag groups** — runs of consecutive edits sharing the same non-empty `tag` (e.g. all 2,653 patches from `ptm import` tagged `ptm_import`, or the 4 edits from a FA24-swap workflow tagged `fa24_swap`) collapse to a single chevron header by default once they exceed 10 edits. Header shows aggregate flags (S/E), tag name, count, and a Jump-to-end-of-run action. Click the chevron to expand; a "Collapse expanded groups" button at the bottom re-folds all in one click.
- **AccessPort Browser — filter, sortable columns, human-readable sizes** — file-table now has a per-subdir substring filter input, clickable sortable headers (Name / Size / Modified), and KB/MB/GB-formatted Size column with raw-byte tooltip on hover. Footer shows "Showing N of M" when filter is active.
- **AccessPort Browser — Device tab** — new 5th tab surfacing the AP's `/settings` (plain ASCII INI per RE2 — rendered as a 2-column key/value table) and `/backupcksum` (currently-flashed-ROM MD5, with "Copy MD5" affordance pending the library-cross-reference work from `findings/handoffs/HANDOFF-to-analyst-2026-06-13-ap-browser-ux.md` Tier 1 #2).
- **AccessPort Browser — daze-recovery card** — any AP operation that fails with a daze-signature error (TransportTimeout, LIBUSB_ERROR_PIPE, LIBUSB_ERROR_TIMEOUT) latches a prominent danger-colored card at the top of the panel explaining the firmware-wedge condition (docs/34 §4.2) and offering "Reset connection" (auto-reconnects when the AP is detected back on USB) + "Dismiss" actions. AP-enumeration chip in the card shows whether the user has replugged yet. Replaces the old per-error "AP may be in daze recovery" status-line hint.

### Changed
- **`apply_fa24_swap` refactored to a data-driven loop** — the 4 hardcoded `apply_op_table` calls (each duplicated across basemap-vs-defaults branches, ~60 lines) collapse to a single pass over a `kWorkflowTables` descriptor array. Adding a 5th edit (when the AVCS TGV-open variants land) is now a one-line append.
- **First-run wizard rewrite** — Welcome / Units / Theme / Demo steps rewritten in the design philosophy set by yesterday's jurisdiction rewrite. Lead with what the choice does in plain language, "Not sure?" reassurance line, concrete use-case blurbs over implementation-detail blurbs. Imperial radio disabled-with-tooltip ("coming in a follow-up release") since no conversion layer is wired yet. Esc wired to the skip flow with a `skip_wizard` lambda deduplicating the body across window-X / Skip button / Esc.
- **Sidebar table list now hierarchical** — pack categories like `fuel - injectors - pulse` split on the first ` - ` into a top-level group (`fuel`) and a sub-group label (`injectors - pulse`). Top-level and leaf-level both default-CLOSED so a fresh project shows ~9 group headers instead of 91 flat folders. Per-row MDL2 grid icon + per-header folder icon dropped (the indent + arrow already convey hierarchy). S/E policy badges still right-aligned. Glossary hover works at both levels.
- **FA24-swap pack-support check** is now purely pack-declared — the transitional hardcoded table-presence fallback that was falsely qualifying packs by table-name presence alone (lf75404h, lf75404s, lf79100p, lf9c102p, lf9g003t) is dropped. Future packs opt in by adding `[[workflow]]` to their TOML.
- **`definitions/impreza/lf79101p.toml`** now declares `extends = "lf79103p"` so the third-party-installed-tune pack inherits the LF79103P table catalog (same firmware family; CID descriptor at 0x37C51 is the only difference). `checksum_type` restated explicitly so `merge_over` doesn't drop the COBB-specific `per_install_block_crc32`.

### Fixed
- **`Definition::from_file` now resolves `extends`** — the single-file loader (used by `Project::open` for the project's `def_path`) silently skipped extends resolution, so packs relying on inheritance loaded zero inherited tables at runtime and workflow guards returned false against valid project state. Adds `find_sibling_pack_file` (flat-file counterpart to `find_sibling_pack_dir`) with cycle-protected recursion. `pack-info lf79101p.toml` now reports 293 tables (inherited) instead of 0.

### Tooling
- `.pre-commit-config.yaml` — local mirror of the CI `clang-format (required)` lane, plus trailing-whitespace, end-of-file-fixer, yaml/toml/merge-conflict checks. Install: `pip install --user pre-commit && pre-commit install`. Stops format drift at commit time before CI.
- CI smoke now exercises `pack-info --json fixtures/demo-pack/pack.toml` on every matrix lane — guards the demo pack against drift + exercises the `subuwutuner.pack-info.v1` JSON emitter.
- **CI workflow-eligibility gate** — every matrix lane runs `workflow-list definitions/impreza/lf79103p.toml`. Exits 1 if any declared workflow has a missing required-table id, so a future pack regen that drops one of `fa24_swap`'s required tables trips CI immediately rather than silently disabling the welcome card / Tools menu entry.

### Tests
