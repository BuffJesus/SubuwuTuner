# SubuwuTuner definition packs

One TOML per ROM CID. Each file is a self-contained `[pack]` with its own
`[[identification]]`, `[[scaling]]`, `[[axis]]`, and `[[table]]` records.

```
definitions/
├── va/   8 packs — WRX VA (2015-2021)
│         lf75404h, lf75404s, lf75600h, lf79103p,
│         lf9c102p, lf9d012h, lf9g003t, lf9l000e
└── vb/  18 packs — WRX VB (2022+, through MY2026)
          lhbh800{b,c}00g, lhbh900{b,d}00g, lhbhb10b00g,
          lhbhc01c00g, lhbhd00b00g, lhbhe00{b,c}x0g,
          lhbkc40{m,p}00g, lhbkc50my0g,
          lhbp300d00g, lhbp301b00g, lhbp400bz0g,
          lhbt120ba0g, lhbt210{u,v}b0g
```

## Provenance

Generated by `tools/defgen/defgen.py` from `*.facts.xml` inputs in the
developer's analyst-side workspace (`D:\Documents\atlas-personal\`, not in
this repo). Those inputs are themselves fact-stripped derivatives of public
RomRaider XML — names replaced with stable `va_tNNNN` / `vb_tNNNN` IDs,
descriptive prose dropped, only addresses, axis sizes, storagetype, endian,
and scaling expressions retained.

Clean-room rules in `docs/01-reverse-engineering.md` and
`docs/15-clean-room-engineering.md` apply: facts (addresses, scaling math)
are not copyrightable; expression (names, descriptions) is and gets
stripped. The pipeline is:

```
public RomRaider XML
  → analyst-side scrubber (atlas-personal/scrub_names.py, off-repo)
    → *.facts.xml (off-repo)
      → tools/defgen/defgen.py
        → definitions/{va,vb}/*.toml (this directory)
```

## Status caveats

- **Scaling math** is exact for all linear expressions, including the
  `(x)/N` and chained `((x)-A)/B*C` forms that dominate Subaru scalings.
  `/*RSHIFT(N)*/` and `/*LSHIFT(N)*/` hardware-shift hints are interpreted
  as `2^-N` and `2^N` linear factors (standard Subaru fixed-point
  convention); re-verify against real ROM data when a bench rig is
  available.
- **`/*INVERSE_DIVIDE*/` and `/*AND*/` markers** are flagged as non-linear
  and emit identity scaling with a defgen warning — these need hand-edit
  to model as piecewise or AND-mask scaling.
- **Unresolved axis storage** — a small number of 2D tables (5 in VA, 23
  in VB) have an X axis named in the source XML but no `storageaddress`
  after inheritance flatten. `defgen` demotes these to scalar
  (`dimensions=0`) with a per-pack warning rather than emitting a broken
  reference.
- **Names** are placeholder slugs (`va_t0001`, `vb_t0512`). Friendly names
  belong in a separate hand-edited mapping file, not in this pack — that
  keeps the clean-room boundary clean.

## Regenerating

```
python tools/defgen/defgen.py path/to/va_wrx.facts.xml -o definitions/va/
python tools/defgen/defgen.py path/to/vb_wrx.facts.xml -o definitions/vb/
```

`--apply-to-pack` is the right mode if you've hand-edited a pack and want
to layer in new records from an updated XML without losing your edits.

## Loading from C++ / CLI

```
subuwutuner-cli pack-info definitions/va/lf9c102p.toml
subuwutuner-cli table-list --def definitions/va/lf9c102p.toml
subuwutuner-cli dump-table --def definitions/va/lf9c102p.toml --table va_t0001 stock.bin
```
